# ZAPL Recorder

Лёгкий рекордер и стример экрана в духе OBS Studio: интерфейс на Rust (egui),
захват и кодирование — через ffmpeg. Рассчитан на слабые машины: Celeron,
4 ГБ ОЗУ, встроенная графика.

> [!CAUTION]
> Проект в стадии прогрессивной разроботки! Поэтому вполне возможны баги недочёты и другие проблемы именно на вашем железе! Просьба указывать проблемы для улучшения софта в `Issue` или создавать `Pull Requests` если можете сделать стабильный форк кода!

## Возможности

- **Сцены и источники**: захват экрана (монитор), окно по заголовку, браузер,
  картинка/логотип. Источники можно включать, скрывать, двигать по слоям и
  масштабировать в координатах холста.
- **Режимы работы** (пресеты): запись игры, запись работы, стрим работы,
  стрим игры, запись ИИ, стрим ИИ. Пресет задаёт разрешение, FPS, битрейт и
  настройки x264.
- **Запись**: MKV (устойчив к падению) или MP4, аппаратные кодировщики
  NVENC / Quick Sync / AMF / VAAPI либо x264.
- **Стрим**: Twitch, YouTube, Kick по ключу и любой свой RTMP-сервер.
- **Звук**: микрофон и системный звук, громкость и Mute по каждому источнику.
- **Превью** программы с рамками источников; работает отдельным ffmpeg на
  5 кадрах/с и останавливается во время записи, чтобы не тратить CPU.
- **Таймер и статистика**: время записи крупно внизу слева, для стрима —
  FPS, битрейт и число потерянных кадров из лога ffmpeg.
- **Портативная сборка**: папка с exe, ffmpeg, документацией и примерами
  конфигурации, а не один файл.

> «Режимы ИИ» — это профили для скринкастов нейросетей (читаемый текст, долгие
> сессии). Встроенной нейросети в программе нет.

## Сборка через GitHub Actions

Готовые бинарники в репозитории не лежат — их собирает workflow
`.github/workflows/build.yml` на `windows-latest` и `ubuntu-22.04`.
Локально собирать ничего не нужно.

1. Запушьте репозиторий на GitHub.
2. Откройте вкладку **Actions** → workflow **build** → **Run workflow**.
   Можно и просто запушить в `main`/`master`: сборка стартует сама, а на
   pull request выполняется проверка.
3. Дождитесь двух зелёных job'ов: `Windows x64` и `Linux x64`.
4. На странице запуска внизу появится блок **Artifacts**:
   - `zapl-recorder-windows-x64.zip`
   - `zapl-recorder-linux-x64.zip`
5. Скачайте нужный архив и распакуйте — внутри целая папка:

```
ZAPL-Recorder/
├─ zapl-recorder(.exe)
├─ bin/ffmpeg               статическая сборка, уже в комплекте
├─ run-windows.bat
├─ run-linux.sh
├─ config.example.json
├─ README.md, README-FIRST.txt
├─ docs/QUICKSTART.md
├─ THIRD-PARTY.md
└─ LICENSE
```

Workflow сам скачивает ffmpeg (Windows — gyan.dev essentials, Linux —
johnvansickle static), запускает `cargo test --locked` и `cargo build
--release --locked`, а затем упаковывает папку в zip.

### Релиз по тегу

Если запушить тег вида `v0.1.0`, те же два архива автоматически попадут в
**GitHub Release**:

```bash
git tag v0.1.0
git push origin v0.1.0
```

## Быстрый старт

1. Скачайте архив для своей ОС из **Actions → Artifacts** (или из Release).
2. Распакуйте папку `ZAPL-Recorder` целиком — ffmpeg лежит в `bin/`.
3. Запустите `zapl-recorder.exe` (Windows) или `./run-linux.sh` (Linux).
4. В правом верхнем углу должен появиться зелёный статус ffmpeg.
5. Нажмите «Начать запись». Файл появится в `Видео/ZAPL Recorder`.

Настройки и ключи стрима:

- Windows: `%APPDATA%\ZAPL-Recorder\config.json`
- Linux: `~/.config/ZAPL-Recorder/config.json`

На Linux файл создаётся с правами `600`.

## Режимы

| Режим | Разрешение | FPS | Битрейт | Особенность |
|---|---|---|---|---|
| Запись игры | 1280×720 | 60 | 4 000 | движение, ultrafast |
| Запись работы | 1280×720 | 30 | 2 500 | `tune stillimage`, резкий текст, для слабого CPU |
| Стрим работы | 960×540 | 30 | 2 000 | стабильно на слабом интернете |
| Стрим игры | 1280×720 | 30 | 3 000 | ключевой кадр 2 с |
| Запись ИИ | 1280×720 | 30 | 3 000 | код и таблицы, долгие сессии |
| Стрим ИИ | 1280×720 | 30 | 2 500 | скринкаст нейросетей |

По умолчанию включён режим «Запись работы» (720p30, x264 `ultrafast`, MKV, превью выключено) — эта конфигурация стабильно работает на AMD A4-9120 с встроенной Radeon R3 и 4 ГБ ОЗУ. Разрешение и FPS можно скорректировать вручную в «Настройки → Видео».

## Стрим

1. «Настройки → Стрим», добавьте площадку (Twitch / YouTube / Kick / свой RTMP).
2. Вставьте ключ потока. Адрес RTMP подставляется автоматически.
3. Нажмите «Начать стрим».

Ключи хранятся локально в `config.json` в открытом виде (на Linux — с правами
600). Не выкладывайте конфиг в публичные репозитории.

Одновременная трансляция на несколько площадок в этой версии не поддерживается:
выберите активную площадку и запустите стрим.

## Локальная сборка (необязательно)

Если всё же нужно собрать самому:

```bash
cargo build --release --locked
cargo test --locked
```

Требуется Rust 1.85+.

- **Windows**: MSVC Build Tools с компонентом «Desktop development with C++»
  (нужен `link.exe`), либо GNU-тулчейн `x86_64-pc-windows-gnu`.
- **Linux**: зависимости для egui/winit:

```bash
sudo apt install pkg-config libxkbcommon-dev libxkbcommon-x11-dev \
  libwayland-dev wayland-protocols libx11-dev libxi-dev libxcursor-dev \
  libxrandr-dev libxinerama-dev libgl1-mesa-dev libegl1-mesa-dev
```

ffmpeg для компиляции не нужен — он требуется только при запуске. Положите
`ffmpeg` в `bin/` рядом с бинарником или установите в `PATH`. Готовый бинарник:
`target/release/zapl-recorder` (`zapl-recorder.exe` на Windows).

Для источника «Окно» на Linux нужен `xdotool`.

### Сборка под слабый CPU (AMD A4-9120 / Excavator)

Если собираете локально на целевом железе, добавьте флаг архитектуры для лучшей производительности:

```bash
RUSTFLAGS="-C target-cpu=bdver4" cargo build --release --locked
```

`bdver4` соответствует архитектуре Excavator (A4-9120). В Cargo.toml уже выставлен `opt-level = "z"` (оптимизация по размеру — лучше попадание в инструкционный кэш на слабых процессорах), `lto = true` и `codegen-units = 1`.

## Как это работает

Композиция повторяет логику OBS: снизу чёрный холст (`color` в ffmpeg), выше —
источники в порядке списка (первый в списке — верхний слой). Каждый источник
масштабируется в свой прямоугольник и накладывается фильтром `overlay`.
Звук сводится `amix` с громкостью по каждому источнику. Готовая команда
ffmpeg видна в «Инструменты → Журнал и команда ffmpeg».

Захват экрана на Windows идёт через DXGI (`ddagrab`), если сборка ffmpeg его
умеет, иначе через GDI (`gdigrab`). На Linux — `x11grab`.

## Производительность

- DXGI забирает кадры с GPU почти без нагрузки на CPU; GDI заметно дороже.
- На слабом CPU: 720p30, x264 `ultrafast`, MKV, превью выключено.
- На NVIDIA/Intel/AMD: аппаратный кодировщик, x264 не участвует.
- Превью автоматически останавливается на время записи.
- Стрим и запись — один процесс ffmpeg без промежуточных файлов.

## Ограничения

- Браузерный источник — это захват области экрана. Окно браузера открывается
  рядом (`--app`, размер и позиция из карточки источника), но его нельзя
  перекрывать, сворачивать и уводить с заданного места. Это не встроенный
  браузерный движок.
- Источник «Окно» на Linux требует `xdotool` и видимое окно.
- Wayland — только через XWayland.
- Только RTMP; SRT и мультистрим не реализованы.
- Список мониторов ограничен индексами 0–3.
- Горячих клавиш нет: управление кнопками.
- Системный звук на Windows требует `virtual-audio-capturer`; на Linux —
  monitor-источник PulseAudio.
